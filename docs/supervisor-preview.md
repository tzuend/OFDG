# Supervisor numerical preview

The approved laptop preview is separate from `quick`, `full`, and thesis assets.
Its configuration is `experiments/preview_manifest.json`. The six-page brief is
`output/pdf/supervisor-preview.pdf`; measured data live in
`measurements/study/preview/`.

## Reproduce or resume

```sh
make -j2 release reference-solver
python3 scripts/run_preview.py --dry-run
python3 scripts/run_preview.py
python3 scripts/analyze_preview.py
```

The runner resumes completed checks only if the source/configuration/executable
fingerprint matches. A changed configuration or executable requires a new directory:

```sh
python3 scripts/run_preview.py --output measurements/study/preview-new
python3 scripts/analyze_preview.py --input measurements/study/preview-new
```

Analysis uses NumPy and Matplotlib; PDF generation uses ReportLab. The analyzer
uses the bundled Codex PDF Python when present, otherwise the current Python.
`--pdf-python /path/to/python` overrides that choice. `make study-preview` combines
build, run/resume, and analysis. The PDF path is stable and is regenerated by analysis.
Neither analysis script writes thesis figures or changes the full-study approval.

## Resource policy

Cases run sequentially. One rank is used for 1D and 8² grids; up to two ranks for
larger 2D grids, capped at half the detected logical processors. If detection fails,
one rank is used. OpenMP and common BLAS thread counts are forced to one; MPI
oversubscription is not enabled. This laptop has eight physical/logical processors.

The runner monitors each process tree every 0.2 seconds, imposing 4 GiB RSS and
300 seconds per check. Aggregate solver/reference wall time is checkpointed. No
new checks start after 2,700 seconds, and a check cannot consume the remaining
3,600-second total budget. An interrupted uncheckpointed check is charged a full
300 seconds on resume. Larger resolutions of a method/case are skipped after a
smaller resolution reaches its resource ceiling. Failed numerical checks remain
visible and are never silently replaced by a shorter physical evolution.

The recorded preview completed 103 solver runs (including three CFL-halving
checks) and four reference solves in 440.73 seconds. The sampled maximum process
tree RSS was 118 MiB. Focused checks took about two seconds. Compilation and
plot/PDF preparation are not included in solver wall time. Peaks are sampled,
not a kernel-enforced memory reservation. No statistical timing claim is made.

## Numerical conventions

- RK4 throughout; scalar CFL 0.15, Euler CFL 0.30. Default OFDG cadence is after
  a full step; default OEDG cadence is after each RK stage. Euler positivity is
  enabled for every method, including DG. No per-method tuning was used.
- `advection -piecewise` selects 2021 Example 1(b). The initial/exact evaluator
  wraps coordinates periodically. Default smooth data and interfaces are preserved.
- `euler -outflow` copies the interior conservative trace to the exterior at
  non-wall boundaries. The preview uses this for problem 6. Existing fixed-state
  and reflecting-wall behavior remains the default.
- Scalar and Euler profile exports retain `center` and `polynomial` sample kinds
  and add `cell_average`. In 1D, `polynomial` has 21 samples per cell, including
  both endpoints. In higher dimensions it retains the finite-element nodes.
- Cell averages use physical quadrature weights. Euler averages **conservative
  variables first**; reported velocity and pressure in `cell_average` rows are
  derived from that state, not averages of velocity and pressure. Plot locations
  are mapped reference centers, not necessarily physical centroids.
- The new helper integrates curved elements using the existing geometry-aware
  quadrature. Its test uses an exactly representable physical x² on a quadratic
  map, distinguishing the analytic average 1/3 from the center value.
- WENO5/SSPRK3 Euler references at 2,048/4,096 cells are independent of the DG
  implementation. Fine densities are averaged in pairs before comparison with
  coarse reference densities. Neither is claimed exact. Burgers after shock has
  no independent error oracle in this preview.
- Periodic scalar total changes are checked. Euler open-boundary total changes
  are not conservation errors without boundary-flux accounting.
- Curved 2D advection is an adaptation: unit square, velocity (0.7,0.3),
  sin²(pi(x+y)), existing static cubic deformation. Native NURBS is not used.
- Error slopes above P+1 on these grids are not claimed as superconvergence.
  Finest-P3 time-step sensitivity was below 0.003%; no adaptive rerun was needed.

## Validation

```sh
make build/release/tests/test_preview
python3 tests/run_bounded.py python3 tests/test_preview_runner.py
```

This checks analytic physical means, 21-point export, piecewise data, outflow
against the physical boundary flux, fixed-boundary compatibility, resource
termination, processor caps, and serial/two-rank curved exported means. All six
PDF pages are rendered and visually inspected before delivery.

The profile CSVs and logs are intentionally retained (about 47 MB for this run).
`results.json` stores exact commands, source fingerprint, revisions, status,
runtime and RSS; `results.csv` flattens metrics. `convergence.csv`, `analysis.json`,
and `figures/` contain the preview analysis. The source fingerprint includes
executables; `source.patch` records tracked changes at the time of execution.

## Presentation review

The two-agent review is recorded in `docs/supervisor-preview-review.md`.
The revised brief uses shared legends, distinct method styles/markers, scalar
filtered-method differences, and a Shu-Osher wave detail. The 2D density cuts
now reconstruct the saved P2 tensor polynomials at the same physical y=0.740
on both grids. Coordinates that differ only by floating-point roundoff are
clustered before interpolation; cells remain separate at interfaces. An analytic
tensor-polynomial check and node-reproduction checks run during analysis.
Text fonts are embedded (Arial on this Mac, or DejaVu Sans on Linux).
